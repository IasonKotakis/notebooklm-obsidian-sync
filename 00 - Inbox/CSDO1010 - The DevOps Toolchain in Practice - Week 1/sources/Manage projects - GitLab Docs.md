## Core Content
This GitLab documentation page covers the core workflows for managing [[GitLab Projects]], including how to view, star, archive, fork, and delete projects. It explains the project overview page, project visibility, and how to interact with projects using the [[GitLab API]] or direct URL access via project ID.

## Key Points
- [[GitLab Projects]] are the central unit of work in GitLab — files, code, and most features are scoped to a project
- The **Project Overview** page displays repository contents, metadata (stars, forks, commits, branches), storage size, README, and optional configs like [[CI/CD configuration]] and [[GitLab Pages]]
- Projects can be filtered and browsed by status (active, inactive, trending), role (owner, member), or [[programming language]]
- **[[Forking]]** creates a personal copy of a project under your own namespace, enabling independent development and [[merge requests]] back to the source
- Projects can be archived (read-only, hidden from listings) or deleted (with an optional delayed deletion period and restore option), managed under **Project Settings**
